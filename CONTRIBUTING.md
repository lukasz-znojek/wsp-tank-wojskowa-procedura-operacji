# Zasady współpracy

## Przed zmianą

- Przeczytaj `PROJECT_CONTEXT.md`, `AGENTS.md` oraz właściwą procedurę lub szablon.
- Określ, czy zmiana dotyczy procedury, formatu artefaktu, przykładu czy architektury.
- Sprawdź, czy istnieje ADR obejmujący daną decyzję.

## Standard zmian

- Jeden pull request powinien rozwiązywać jeden spójny problem.
- Opis PR musi wskazać cel, zmienione artefakty, wpływ na schematy i sposób walidacji.
- Nowe przykłady muszą być wyraźnie oznaczone jako fikcyjne.
- Zmiany mające wpływ na struktury JSON wymagają aktualizacji odpowiedniego schematu.

## Przegląd

Przegląd sprawdza zgodność z zakresem symulacyjnym, jednoznaczność języka, kompletność wymaganych sekcji, działanie odnośników oraz spójność procedur, szablonów, przykładów i schematów.
